# A-06: 기준·개선 버전 평가

평가는 **개발용 오류 주입 시험**과 **로컬 실모델의 제한된 작성 단계 비교**로 분리한다. 오류 주입 검출률을 실모델의 실제 오류 발생률이나 전체 답변 정확도로 보고하지 않는다.

## 재현

```bash
# 외부 호출 없이 기준/개선을 각각 18회: 시나리오 3 × REST/SSE 2 × 반복 3
./.venv/bin/python -m evaluation.run --mode offline --repetitions 3 \
  --improved-ref 56a7b12e88976d97ce4dc02426f1aea342452b1d \
  --output /tmp/skala-offline.json

# 이미 설치된 로컬 모델만 허용하며 모델 다운로드·유료 API 호출은 하지 않음
# Ollama가 꺼져 있으면 별도 터미널에서 OLLAMA_HOST=127.0.0.1:11434 ollama serve
./.venv/bin/python -m evaluation.run --mode ollama --model qwen3:8b --repetitions 1 \
  --improved-ref 56a7b12e88976d97ce4dc02426f1aea342452b1d \
  --output /tmp/skala-ollama.json

# 평가 도구 자체 검사 + 기존 회귀
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python tests/run_pinned_baseline.py
node --test tests/ui.test.cjs
```

같은 경로의 결과가 있으면 중단한다. 의도적으로 교체할 때만 `--overwrite`를 준다. 원시 JSON과 같은 이름의 Markdown 보고서를 함께 만든다. 실패를 조용히 건너뛰지 않으며 작업 오류·계약 위반도 결과에 저장하고 종료 코드 1로 보고한다. Ollama 사전 확인에서 연결·모델이 없으면 측정 없이 오류로 종료하고 성공 결과를 만들지 않는다.

## 소스와 실행 조건

- 기준은 초기 v2 커밋 `447db631b079f6c8b5e67c3b2bfce4dbaf59169f`, 개선은 A-05 완료 커밋 `56a7b12e88976d97ce4dc02426f1aea342452b1d`다. A-06은 운영 코드를 변경하지 않는다.
- 두 소스의 `agent`, `server.py`, `data`를 각각 임시 디렉터리에 Git archive로 추출한다. 같은 Python·설치 의존성·평가 코드·fixture를 복사해 **별도 프로세스**에서 실행한다. 체크아웃과 사용자 DB를 바꾸지 않는다.
- 평가 질문을 incident로 고정하고, 같은 모니터링·매뉴얼 태스크를 동일하게 제공한다. Fast 모델·실제 MCP 네트워크·대상 추론 품질은 평가하지 않는다. 원본 데이터는 매번 사본을 반환하고 기준 시각·요청 ID를 고정한다.
- 시연용 `asyncio.sleep(0.35)`는 양쪽 모두 0초로 바꾼다. 임의 수치 변동·MCP 재시도는 사용하지 않는다. 따라서 측정 지연은 이 **통제 환경의 요청 wall-clock**이며 운영 서비스의 전체 지연이 아니다.
- `.env`를 읽지 않고 tracing을 끈다. API는 메모리 ASGI로 호출하며 SQLite는 요청별 임시 폴더에만 만든다. 오프라인 worker는 소켓·DNS도 차단한다.
- 결과에 커밋, agent/data tree·server blob, 평가 코드와 두 fixture SHA-256, Python·의존성 버전, 플랫폼과 모델 digest를 남긴다. 파일 내용 해시가 실행 당시 코드·자료를 식별한다.

이번에 보관한 두 측정의 실행 코드와 최초 원시 결과는 커밋 `59957ac718ffff7ceb4dfbf3f56ccfa0df2bc8b5`에 고정되어 있다. 이후 CLI의 출력 경로·클라우드 모델 거부 검사와 실행 소스 추적 정보를 보강했다. 보관한 JSON에는 `provenance_annotation`으로 당시 커밋과 최초 파일 SHA-256만 추가했으며, 측정값·집계와 기존 `runner_sha256`은 바꾸지 않았다. 이 해시는 현재 CLI가 아니라 당시 소스에 대응한다. 테스트가 해당 커밋의 소스·최초 결과 및 재집계를 대조한다. Markdown 표시에서만 줄 끝 공백을 정리했으며 모델을 다시 호출하지 않았다.

### 로컬 모델의 추가 조건

설치된 `qwen3:8b`를 같은 모델 digest·설정으로 사용한다. `temperature=0`, `seed=42`, `num_predict=2048`, `num_ctx=8192`, `think=false`, `stream=false`, 요청 제한 120초다. 준비 호출 1회는 결과 지연·사용량에서 제외한다. 입력의 query·원본 스냅샷은 같으며 **기준의 번호형 자유 텍스트 / 개선의 JSON Schema 출력·피드백은 변경 자체의 일부**다. 같은 프롬프트를 사용한 실험은 아니다.

양쪽의 실제 writer를 호출하되 평가 전송만 동일한 비스트리밍 HTTP로 통제한다. 운영 백엔드의 기본 thinking/스트리밍·자동 context 조건과 다르다. Ollama의 생성 옵션과 thinking 제어 형식은 [공식 API 명세](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml)를 참고했다. 모델은 로컬 고정 주소에서만 호출하며 클라우드 모델·다운로드·OpenAI 키를 사용하지 않는다.

기준→개선 순서, 모델 캐시와 로컬 기기 작업의 자원 경합은 엄격히 통제하지 않았다. 일부 검사는 실모델 실행 중 병행했다. 질문당 1회여서 지연의 통계적 우열이나 운영 성능을 일반화할 수 없다. 토큰은 Ollama 응답의 실제 `prompt_eval_count + eval_count`이며 `usd`는 1천 토큰당 $0.005라는 가상 단가 추정이다. 외부 API 청구액이 아니다.

### 2026-10-21 실행 요약

오프라인 검증기 비교는 정상 6개·오류 18개다. 기준의 오류 검출은 **0/18**, 개선은 **18/18**이고 정상 오탐은 양쪽 **0/6**이다. 서로 대응하는 자유 텍스트와 JSON 계약을 비교한 개발용 시험이다.

통제 파이프라인은 버전별 18회(시나리오 3 × 경로 2 × 반복 3), 총 36회다. 최초 성공은 1회, 오류 후 수정은 2회, 반복 실패는 3회 작성으로 재현됐다. 반복 실패에서 기준은 REST/SSE 각각 3/3을 강제 통과하고 오류 초안을 저장했다. 개선은 각각 0/3 통과, 오류 초안 저장 0/3이었다. SSE 검증 전 토큰은 기준 9/9 요청, 개선 0/9 요청에서 전송됐다. 기준의 원시 프롬프트는 SSE 9/9에 있었고 개선은 0/9였다.

실모델은 질문 3개를 버전별 1회 실행했다. 전부 HTTP 작업 오류 없이 끝났고 모든 호출은 `done_reason=stop`이었다. 생성 한도 도달을 성공으로 잘못 센 결과는 없었다.

#### 원문을 읽고 확인한 사항

다음은 개발 에이전트의 원시 응답 대조이며 독립적인 인간 검토나 자유 문장 전체의 의미 채점이 아니다.

- 기준 CPU 응답에서 확인한 CPU·메모리·상태 수치는 제공한 스냅샷과 같았다. 기준 메모리 응답도 cache-service 92.75%, web-01 44.5%를 그대로 인용했다. 따라서 구조화 검증 도입만으로 기준 실모델이 실제 수치를 모두 잘못 말했다고 주장하지 않는다.
- 기준 unknown 응답도 미인식 상태와 매뉴얼 없음을 알렸지만, unknown 원본의 CPU·메모리 0%를 답변에 재인용했다. 개선은 이를 인용 가능한 실측으로 취급하지 않고 최종 결과에서 제외했다.
- 개선 CPU의 첫 초안은 `web-01`의 빈 알림 배열 `[]`에 없는 `alerts.value=""`를 관측으로 추가했다. 검증 피드백 후 두 번째 초안에서는 이를 제거해 통과했다.
- 개선 메모리 질문은 같은 빈 알림 문자열을 세 번 반복했고 `value_mismatch`로 끝났다. 핵심 수치 7개는 맞았지만 전체 초안을 임의 통과시키지 않고 원본 기반 대체 답변을 반환했다. 구조화 diagnosis의 포함률 0/7은 대체 reply의 사실 누락을 뜻하지 않는다.
- 개선 unknown 초안은 인용 불가 근거를 반복 참조했다. 세 번 후 실패로 종료해 잘못된 가설·조치를 공개하지 않았다.

이 결과의 중심은 **실패를 탐지하고 안전하게 종료하는 경계**다. 이번 소규모 실측에서는 응답 속도나 구조화 진단 완성률이 개선됐다고 말할 수 없다. 운영 프롬프트·정책을 이 평가에서 고치거나, 결과가 좋아질 때까지 사례를 바꿔 재측정하지 않았다.
