# A-01: 기준 동작과 고정 평가 데이터

기준 코드: `447db631b079f6c8b5e67c3b2bfce4dbaf59169f`의 **v2**. A-01에서는 실행 코드를 변경하지 않는다. 아래 테스트의 통과는 기존 동작이 재현된다는 뜻이며, 잘못된 답변이 해결되었다는 뜻은 아니다.

## 재현

저장소 루트에서 기존 가상환경으로 실행한다. 추가 테스트 패키지는 필요하지 않다.

```bash
# 현재 코드의 특성·회귀 검사
./.venv/bin/python -m unittest discover -s tests -v

# 같은 테스트와 fixture를 개선 전 코드에 적용
./.venv/bin/python tests/run_pinned_baseline.py
```

두 번째 명령은 로컬 Git에서 기준 커밋의 `agent`, `server.py`, `data`를 임시 폴더로 추출하고 현재 테스트를 복사해 실행한 뒤 폴더를 삭제한다. 작업 브랜치를 전환하거나 원격에 접속하지 않는다. 기준 커밋이 로컬에 있어야 한다. 두 명령은 같은 Python 인터프리터를 사용한다.

`tests/support.py`는 tracing을 끄고 각 테스트에서 소켓 연결·DNS 조회를 차단한다. 실제 모델 대신 기존 `FastLLM`·`QualityLLM`, 실제 MCP 대신 엄격한 `FixtureMCP` 대역을 쓴다. 서버 import 시 `load_dotenv`를 막고 FastAPI lifespan을 실행하지 않는다. 실제 MCP 시작과 기본 DB 생성은 테스트에서 금지하며, ASGI 요청은 메모리 안에서 처리한다. SQLite는 테스트별 임시 폴더에만 만든다. 사용자 `.env`나 `session.db`는 읽거나 초기화하지 않는다.

데모의 0.35초 태스크 지연과 재시도 backoff는 테스트에서만 실제 스케줄링 지점이 남는 0초 대기로 교체한다. 따라서 테스트 수행 시간이나 `parallel_elapsed`는 운영 지연 비교 자료로 사용할 수 없다. 비용은 기존 fake 모델의 가상 단가 결과이며 실제 청구액이 아니다.

## 고정 데이터와 수동 정답

[diagnosis_cases.json](../tests/fixtures/diagnosis_cases.json)은 평가 입력 데이터다. 실행 코드의 모델이나 확정된 API 스키마가 아니다. A-02·A-03에서 모델을 확정하면 이 데이터와 연결하는 방법을 함께 결정한다.

- 기준 시각: `2026-10-20T09:00:00+09:00`.
- 근거 9개: 모니터링 5개, CPU 매뉴얼과 매뉴얼 없음 안내 각 1개, 다른 요청의 모니터링 1개, 모델 해석 1개.
- 기본 장애 경로는 `payments-service` CPU 91%·메모리 55%, `web-01` CPU 34%·메모리 48%, CPU 급증 매뉴얼을 사용한다. CPU 매뉴얼 본문은 데이터 파일에 고정 복사해 이후 원본 문서 변경에 흔들리지 않게 했다.
- `unknown`의 0 값, CPU 누락, 다른 요청의 ID와 모델 해석은 거부 조건 시험용이며 유효한 원본 관측으로 승격하지 않는다.
- 후보 초안 24개: 수동 기대 판정 `accept` 6개, `reject` 18개. 정답은 [PLAN_A.md](PLAN_A.md)의 초기 범위를 따라 작성했으며 모델 판정 결과가 아니다.

| 종류 | 사례 |
|---|---|
| 정상 6개 | 정수 91, 실수 91.0, 메모리 55%, 복수 시스템, 상태 원문, 알림 원문 |
| 오류 18개 | 값·시스템·측정 항목·단위 불일치, 없는/다른 요청 근거, unknown, 원본 값 누락, 모델 해석 인용, 상태 불일치, 알림 변경, 초안 값 누락, bool 수치, 빈 관측, 가설/조치 출처 누락, 매뉴얼 없음, 구조 파싱 불가 |

`candidate_draft`는 미래 검증기용 제안 형태이고 `expected_a_plan`은 사람이 정한 목표 판정이다. **A-01에서는 이 구조를 판정하는 검증기를 만들지 않았다.** `legacy_draft`는 현재 자유 텍스트 검증기에 넣는 대응 사례다. 이 텍스트들은 의도적으로 30자와 `1)` 조건을 만족한다. 두 표현은 같은 오류 유형을 다루지만 서로 다른 입력 계약이므로, 텍스트 검증 결과를 구조화된 후보 초안의 판정 결과라고 보고하지 않는다.

## 확인 결과

2026-10-20, Python 3.11.15와 프로젝트 `.venv`에서 현재 코드와 기준 커밋 모두 **15개 테스트 통과**. 테스트별 하위 사례 24개는 별도 테스트 수에 더하지 않았다.

| 확인 항목 | 현재 재현 결과 | A안 목표 |
|---|---|---|
| 자유 텍스트 검증 | 30자 이상이며 `1)`가 있으면 통과 | 시스템·항목·값·단위·근거 연결 검사 |
| 오류 주입 | 수동 거부 유형 18개에 대응하는 텍스트가 모두 통과 | 후속 검증기에서 거부 |
| 짧은 답변 반복 | 1·2회 반려 후 3회에 강제 합격, 같은 짧은 본문을 최종 반환 | 3회 실패 후 실패 상태와 확인된 원본 사실 반환 |
| 기본 fake 장애 | 최초 짧은 초안 반려, 두 번째 합격, analysis task 1개 제거, runbook 재계획 1회 | 필요한 회귀 조건 유지 |
| 고정 transient timeout | 재시도 1회 후 복구 | 재시도 회귀 방지 |
| REST/SSE | 최종 답변과 도메인 이벤트 동등, SSE `[DONE]` 1회 | 추가 진단·근거·검증 결과도 동등 |
| SSE 초안 | 1회차 부적합 `AnswerToken`이 첫 `Validation`보다 먼저 노출 | 검증 전 장애 본문 차단 |
| 원시 프롬프트 | fake 대역이 넣은 테스트 문자열이 SSE `FinalAnswer.prompt`에 노출 | 사용자 공개 출력에서 제거 |
| 대화 저장 | v2 REST/SSE 모두 최종 답변만 저장, thread 분리, 임시 DB 재연결 유지 | 회귀 방지 |
| 일반 대화 | history로 이름 회상, MCP·검증 미실행 | 회귀 방지 |
| v1 기본 장애 | legacy 경로, 검증 0회, auth-service 조회 | 기존 경로 유지·검증 비대상 표시 |
| 조회 예외 | 리소스 ValueError가 그래프 밖으로 전파 | 오류를 정상 응답으로 숨기지 않음 |

현재 자유 텍스트 오류 주입 사례의 검출 수는 **0/18**이다. 이 수치는 의도적으로 만든 텍스트 집합에만 해당한다. 실모델이 오류를 생성할 확률이나 개선 후 정확도가 아니며, 미래 구조화 검증기의 성능 측정도 아니다. 정상 유형의 대응 텍스트 6개도 모두 통과했다.

## 후속 사용과 한계

- 특성 테스트 중 오류 통과·강제 합격·초안 노출을 기대하는 항목은 개선 단계에서 의도적으로 실패한다. 해당 단계에서 새 기대 동작으로 테스트를 바꾸고, 기준 버전 비교용 계약은 구분해 유지한다. 기존 오류를 계속 보존하기 위해 실행 코드를 되돌리지 않는다.
- `run_pinned_baseline.py`는 현재의 A-01 테스트 모듈 `tests.test_baseline`과 `tests.test_api_baseline`만 기준 코드에 적용한다. 이 15개는 기준에서 통과하며, 과거 코드에 없는 후속 A안 기능 테스트는 제외한다. A-01 모듈 안의 기대 동작을 바꿀 경우 기준 버전 비교 계약도 함께 분리해야 한다. 전후 평가 자동화는 A-06 범위다.
- fixture ID·필드명은 테스트용 제안이며, 이후 모델 확정 시 대응표가 필요하다. `expected_a_plan`을 실제 검증 결과로 반환하지 않는다.
- 가설의 인과관계와 조치의 효과는 자동 의미 검증 대상이 아니다. 출처 ID 존재 확인과 의미 지지를 구분한다.
- 실제 MCP 프로토콜, 실모델, 실제 서버 포트·브라우저 화면, 지연·비용 품질은 시험하지 않았다. v1은 기본 장애 경로만 확인했으며 전체 동작 커버리지를 주장하지 않는다.
- 키워드 우선순위(`latency`가 `cpu`보다 먼저), 무매칭 시 `db-down`, 시스템 미인식 시 `auth-service` 폴백은 현재 특성으로만 기록했다. A안의 수치 검증으로 해결되는 문제가 아니다.
