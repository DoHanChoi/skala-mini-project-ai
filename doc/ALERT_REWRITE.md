# A-07: 빈 알림의 작성·재작성 안내

승인: A-06 완료 보고에서 이 후보를 제안한 뒤 사용자 “넘어가”(2026-10-21 KST). 이슈 [#17](https://github.com/DoHanChoi/skala-mini-project-ai/issues/17).

## 해결하는 문제

[A-06 실측](EVALUATION.md)에서 메모리 질문의 핵심 원본 사실 7개는 맞았지만 모델이 `web-01`의 `alerts=[]`를 `metric="alerts", value=""` 관측으로 추가했다. 기존 검증기는 `value_mismatch`와 위치를 전달했으나 모델은 세 번 같은 오류를 반복했다.

빈 배열은 유효한 알림 조회 결과지만, 그 배열에서 인용할 알림 항목은 0개다. `eligible_metrics`에 `alerts`가 있다고 해서 인용할 값이 반드시 하나 있다는 뜻은 아니다.

## 변경과 유지하는 계약

- fake·Ollama·OpenAI가 공유하는 작성 프롬프트에 `raw.alerts=[]`이면 알림 관측을 만들지 말라는 안내를 추가한다. 빈 문자열·없음·배열 문자열을 대체 관측값으로 만들지 않으며 같은 시스템의 다른 유효 관측은 유지한다.
- 빈 알림 배열에 문자열 관측을 붙이면 기존 `value_mismatch` 코드와 `observations.<위치>.value` 경로로 계속 거부한다. 메시지는 해당 알림 관측 항목 전체를 삭제하고 다른 유효 관측을 유지하라는 구체적 행동을 안내한다.
- 원본·근거 적격성·진단 스키마·공개 API를 바꾸지 않는다. 검증기가 오류 관측을 자동 삭제하거나 실패를 성공으로 바꾸지 않는다. 다음 모델 출력 전체를 다시 검증한다.
- `[]`와 `[""]`는 다르다. 후자는 실제 원본에 빈 문자열 항목이 있어 기존 원문 일치 규칙을 유지한다. 비어 있지 않은 알림도 원문과 정확히 일치해야 한다.
- 총 3회 작성 상한, 실패 초안·원시 프롬프트 차단, 실패 시 원본 사실만 표시하는 종료 정책을 유지한다. 가설·조치의 의미는 검증하지 않는다.

피드백 예시(고정 안내문이며 실패 초안의 값·시스템·원문을 복사하지 않음):

```json
{
  "code": "value_mismatch",
  "path": "observations.7.value",
  "message": "원본 alerts가 빈 배열이므로 인용할 알림은 0개입니다. 이 경로의 알림 관측 항목 전체를 삭제하고 다른 유효 관측은 유지하세요. 빈 문자열·없음·배열 문자열로 바꾸지 마세요."
}
```

## 검증과 한계

```bash
./.venv/bin/python -m unittest tests.test_alert_rewrite -v
./.venv/bin/python -m unittest discover -s tests -q
./.venv/bin/python tests/run_pinned_baseline.py
node --test tests/ui.test.cjs
```

새 검사 5개는 A-06 실제 실패 초안 세 개의 재생, 별도 시스템·수치의 빈/비어 있지 않은 알림 경계, 입력 비변경·오류 원문 미반사, 세 백엔드 공통 프롬프트, 실제 REST/SSE·임시 SQLite 경계를 다룬다. 모델 대역은 피드백에 삭제 안내가 있을 때만 오류 알림을 제거한다. 두 번째 출력의 정상 관측 전체가 유지되고, 무시하면 세 번 후 실패하는지 확인한다. 일반 대화·v1·기존 검증과 UI는 기존 회귀 검사를 사용한다.

이는 **프롬프트 전달·피드백·실패 차단 동작의 자동 검증**이다. A-07에서 실모델을 새로 호출하지 않았으므로 실제 수정 성공률·지연·토큰 개선을 확정하지 않는다. A-06 수치는 당시 버전의 역사적 결과로 보존하며 이 변경의 성능으로 다시 표시하지 않는다. A-06 사례는 이제 개발 재현 사례이므로 추후 일반화 평가에는 별도 질문이 필요하다.

인용 가능한 원본이 전혀 없는 경우의 조기 종료와 독립 평가 확대는 다음 승인 대상이다.
