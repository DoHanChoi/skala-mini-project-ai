# A-05: 진단과 원본 근거 확인 화면

기존 Vue 채팅 화면에 [A-04 공개 계약](PIPELINE.md)의 `diagnosis`, `evidence`, `validation`을 연결했다. 백엔드 검증 범위는 확대하지 않는다.

## 표시 기준

| 응답 | 화면 |
|---|---|
| 알려진 범위의 `passed=true`와 진단 구역 | 관측값·출처 연결 확인, 작성 횟수, 관측 사실·원인 가설·권장 조치 |
| `failed` / `passed=false` | 진단 검증 실패, 작성 횟수, 서버의 원본 기반 대체 답변, 검증 오류 펼치기 |
| `not_applicable` / `passed=null` | 검증 비대상 · 일반 대화 또는 v1, 기존 답변 |
| 정보 누락·모순·미지원 범위·불완전한 진단 | 검증 상태 확인 불가, 성공으로 해석하지 말라는 안내와 기존 답변 |

- 성공 표시는 관측값·시스템·지표·단위·출처 연결을 뜻한다. 가설은 **추정**, 조치는 **미실행 제안**이며 문장 의미·인과관계·조치 효과를 검사했다고 표시하지 않는다.
- 성공한 구조화 진단만 세 구역으로 표시한다. 실패 상태에서는 `diagnosis`가 잘못 함께 도착해도 표시하지 않고 서버의 확정 `reply`만 보여준다. 확인 가능한 원본도 없으면 서버의 해당 안내를 유지한다.
- 화면은 서버 검증 결과를 표현한다. 브라우저가 원본의 진위를 재인증하거나 별도 사실 검증을 수행하는 계약은 아니다. 알 수 없는 상태를 성공으로 추정하지 않는다.
- 일반 대화의 토큰은 같은 말풍선에 합치며 최종 응답으로 확정한다. 완료 후 단계 표시를 완료 모양으로 바꾸고 중복 제출을 막는다. 최종 응답이 없는 연결 오류는 성공 배지를 만들지 않는다.

## 근거와 원문

관측·가설·조치의 **근거 N** 버튼은 현재 답변의 ID 목록에서만 출처를 찾는다. 답변 번호와 목록 위치로 DOM ID를 만들어 다른 요청의 같은 시스템·근거와 섞지 않는다. 참조가 없으면 버튼은 **출처 없음**으로 비활성화한다.

버튼을 누르면 해당 `<details>`를 열고 `<summary>`로 초점을 옮긴다. 근거 목록에서도 키보드로 펼치고 접을 수 있다. 다음 정보를 제공한다.

- 근거 ID, 모니터링/매뉴얼 종류, 시스템·대상, MCP 서버·실제 도구/URI.
- 조회·관측 시각, 문서 제목·본문 해시, 인용 가능한 항목, 활용 제한.
- 원본 모니터링 값 또는 매뉴얼 본문. unknown·누락 값·없는 매뉴얼은 인용 가능으로 바꾸지 않는다.

**인용 가능**은 수집 근거의 활용 조건 표시다. 문장 의미나 출처 진위를 보증하지 않는다. 원본은 Vue 텍스트 보간으로만 표시하며 HTML·Markdown을 해석하지 않는다. URI를 외부 탐색 링크로 만들지 않는다. 긴 ID·해시·원문은 줄바꿈하고 원문 패널의 높이를 제한해 채팅 입력을 가리지 않는다. 작은 화면을 위한 viewport와 스타일을 포함했다.

## 검증과 재현

```bash
# Node 내장 테스트만 사용하며 별도 npm 패키지는 필요하지 않음
node --test tests/ui.test.cjs

# 기존 백엔드와 고정 기준 커밋 회귀
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python tests/run_pinned_baseline.py

# 사용자의 .env, session.db, 실제 모델·MCP를 사용하지 않는 UI 전용 fixture 서버
./.venv/bin/python tests/ui_fixture_server.py --port 18762
```

fixture 서버 실행 후 `http://127.0.0.1:18762`에서 아래 메시지로 확인한다. 서버는 현재 화면 파일과 요청마다 독립적인 fake 그래프의 확정 응답을 제공한다. 일반 대화는 토큰 이벤트를 한 번 보내는 대역이다. 사용자 DB를 생성하거나 읽지 않으며 운영 서버·실제 MCP·실모델·대화 저장을 검증하는 서버가 아니다. Vue CDN 다운로드는 기존 화면 의존성이다.

| 메시지 | 확인 항목 |
|---|---|
| `payments-service 장애 진단` | 복수 시스템, 2회 작성, 세 구역, 각 출처 버튼·원본 |
| `진단 실패` | 3회 실패, 실패 초안·프롬프트 미표시, 가설·조치 구역 없음 |
| `unknown 매뉴얼없음` | 원본 관측 없음, 인용 불가와 제한 사유·원본 0 값 구분 |
| `매뉴얼없음` | 관측은 표시, 매뉴얼은 인용 불가, 조치 제안 없음 |
| `안녕하세요` | 일반 대화 비대상·답변 표시 |
| `v1 장애 진단` | v1 비대상, 대상 없는 진행 이벤트의 자연스러운 문구 |
| `구버전 진단` | 검증 정보가 없어도 성공 표시를 만들지 않음 |
| `HTML 진단` | 매뉴얼 원본의 HTML·script·javascript 링크가 텍스트로만 표시 |

Node 검사 12개는 실제 화면 스크립트를 VM에서 실행하고 Vue 반응성·SSE·DOM 경계를 대체한다. 상태·구역 선택, 답변별 출처 연결과 초점 이동, 원문 보존, 토큰 합치기, 중복 제출·오류 처리, 비정상 SSE 프레임과 v1 문구를 확인한다. 실제 Vue 렌더링과 접근성 전체를 보증하는 검사는 아니므로 브라우저 확인을 함께 수행한다. 기존 Python 58개와 기준 15개는 백엔드 회귀용이다.

실모델의 품질과 개선 전후 평가는 A-06 범위다. 재접속 후 과거 대화를 화면에 복원하는 기능과 전면 UI 재설계는 이번 범위가 아니다.
